# 两融事件口径 · 基准组合定义提案（待批准，未冻结）

> 建立 2026-10-16。**性质：提案。只设计、不跑计算、不冻结任何阈值。**
> 用途：给判据协议 **R3（经济价值）** 提供分母。R3 的前置就是「用户先冻结组合定义」。
> 硬约束：**不得根据任何新收益结果调参**（本轮不计算收益）；每个参数必须写依据；写不出依据的标「待拍板」。
> 待批准 → 检查一致性（§3）→ 冻结 + 记哈希（§6）→ 才允许进入收益/成本/容量计算。

---

## 0. 一句话结论

提**一套**基准设计：**当日全部事件股等权、持有 5 个交易日、T+1 开盘成交、1 亿本金、三档参与率并列**；与项目既有冻结口径（`backtest.py` 默认费率、§15 静态参与率、`exec5` 收益定义）逐一对齐。
**只有两个参数没有现成依据、需用户拍板**：① 当日事件股数是否设上限；② 同股在持仓窗口内重复事件如何合并。

## 2. 与判据协议 R3 的接口（k 判据的分子分母）

R3 的候选判据是「净优势 > 0 且 `净优势 ÷ 总成本 ≥ k`」。它需要**分子与分母都有定义**：

| 组成 | 是否已有定义 | 说明 |
|---|---|---|
| 毛收益（分子上游） | ✅ 口径 3/4/5/6 | 组合层日频净值，非「事件平均收益」 |
| 费率（分母之一） | ✅ 口径 13 | 0.102pp 往返 |
| 滑点（分母之二） | ❌ **缺口** | 只有未成交占比，**没有价格冲击成本** |
| k 的取值 | ❌ **未冻结** | 用户已裁决：**k=1 与 k=2 同时报，任一都不得作正式判死门槛**，直到给出经济依据 |

⇒ **R3 目前无法给出「总成本」的完整分母**。在滑点成本口径定下来之前，R3 只能出「毛收益 ÷ 费率成本」的**敏感性读数**，不能出判死结论。

## 4. 误杀风险总表（按参数）

| 参数 | 误杀方式 | 缓解 |
|---|---|---|
| 8 同股去重 | 高换手事件的暴露被稀释 → 低估 | 并列报「去重 / 每事件独立」两版，**只作敏感性，不作门槛** |
| 5 不设 N 上限 | 无（只会因事件少而集中） | 披露每日事件数分布与单票最大权重 |
| 10 等比例缩放 | 小资金下整手约束使部分标的落空 | 报「因不足 1 手落空的笔数」，不静默丢弃 |
| 2 剔除涨跌停 | 若信号集中在易封板标的 → 低估 | **必须同报被剔除样本的收益**（判据协议 R4b） |
| 12 三档参与率只报单档 | 隐藏容量敏感性 | 强制三档并列 |

## 5. 待拍板的分歧点（2 条，必须先定才能冻结）

| # | 问题 | 我的建议 | 为什么不能由 agent 定 |
|---|---|---|---|

## 6. 冻结流程（本提案批准后执行，不在本轮）

1. 用户确认 §5 两条分歧点 → 改定稿。
2. 检查 §3 一致性表，确认无遗漏。
3. **冻结**：计算定稿文件 sha256，写入判据协议 R3 行与本文档。
4. **冻结后才允许**跑收益、成本、容量计算；跑数后**不得再改本定义**（判据协议 P1）。

---

## 7. 不做什么

1. **不扫描参数**（N / 持仓期 / 参与率都不做网格）。
2. **不按新收益结果调参**（本轮不算收益）。
3. **不虚构滑点成本曲线** —— 缺口如实标注。
4. **不用本提案淘汰或纳入任何候选**（停手期至 2027-04-11；停手期合规性另见 `两融事件口径_停手期合规核对.md`）。
5. **不把组合骨架（§16 C5 等权 rank 合成）挪到这里复用** —— 那是另一条候选的出口工作。
