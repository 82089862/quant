## 2. 现行机制诊断（先核对原文，再诊断）

### 2.1 F1 的定义

`[原文]` `doc/死因码表.md` 码表：

> | F1 | 多重检验未校正（名义显著，检验次数 ≫ 样本） | `stocks/downturn.py`（20,888 次检验） | Bonferroni / FDR | 在用 |

`[推导]` F1 是「校正缺失」这一类错误的名字，不是「某个具体阈值不过」的名字。判定一个判据是否会把关失败者的死因归档成 F1，看的是**该判据有没有按检验次数校正**，而不是它的数值高低。

### 2.2 DSR 阈值 1.10 的来源与适用条件

`[原文]` `研究方法与验证协议.md` §9.4：

> | 候选 | sr_obs | DSR | sr_bonf | PBO |
> | alpha015 | +0.405 | −0.602 | 1.101 | 100% |
> …（5 候选 sr_bonf 均为 1.101）
> 原始年化夏普 0.4~0.6 看似合理，但搜索 191 个候选的校正阈值是 1.10——**所有候选均低于此线**。

`[核对事实]` `stocks/pbo_dsr.py` 第 46–54 行：

```
z_bonf = norm_ppf(1 - alpha / (2 * n_trials))
sr_bonf = z_bonf / np.sqrt(T)
```

代码默认值 `alpha=0.05`、`n_trials=191`、`T=11`（完整年数）⇒ `3.6517 / 3.3166 = 1.1011`，与 §9.4 表的 1.101 吻合。

`[推导]` 1.10 是**收益空间上的 Bonferroni 校正夏普阈值**，三个输入全部由项目自定（α 取惯例值、N 取项目搜过的候选数、T 取完整年数）。推理步：
- 它由本项目代码计算得出，不是从外部文献直接抄来的常量 ⇒ 不能称之为「理论值」。
- 它随 N、α、T 变化（例如 N 变小 → z 变小 → 阈值变低）⇒ 不能称之为「经验常数」。
- ⇒ **可诊断的不是「1.10 对不对」，而是「N=191 / α=0.05 / T=11 是不是本项目应当采用的输入」**（§8 待裁决）。

`[核对事实]` §9.4 同表另有 DSR 列的 `B = √(2γ ln N)/√T`，代入 N=191、T=11 时 B≈0.98 —— **与 1.10 是两个不同的量**（前者是 DSR 统计量的收缩项，后者是判定线）。引用「校正阈值 1.10」时指的是后者。

### 2.3 A/B 记账线与 F1 的关系

`[原文]` `Alpha191候选分层回测计划.md` §14「性质」：

> 本段属出口。所以下面三条线叫**记账线**，不叫证伪判据；若将来要把它们当筛选判据用，必须**另立防线卡**并等停手期结束。

`[原文]` `研究方法与验证协议.md` §9.4「影响」：

> §14 的 A/B 线判据（「对反转基线分年超额为正 ≥ 7/11」）是**未校正的阈值**，在多重检验框架下等价于 F1（Bonferroni 未校正）。当前防线需要重建——要么降低阈值，要么接受「这 5 个候选也是过拟合」的事实。

`[推导]` 「等价于 F1」应读作**同一缺陷的等价**（固定阈值、未按检验次数校正），**不是数学等价**（A/B 线判的是分年超额胜率，F1 判的是名义显著性，两者统计量不同）。推理步：
- F1 的定义是「校正缺失」（§2.1 原文）；
- A/B 线是固定的 7/11 计数线，未随「搜过多少候选」调整（§14 原文）；
- ⇒ 两者共享「未校正」这一属性，故同码归档合理。

`[核对事实]` **该「等价」的推导过程在协议中未留档** —— §9.4 直接给出结论，没有 «A/B 线如何随 N 变化» 的中间推导或对照算例。按用户要求，诊断阶段**不得先假定它成立再倒推论证**。

### 2.4 PBO 实现与 §9.4 声称的方法不一致（待核实）

`[原文]` `研究方法与验证协议.md` §9.4「背景」：

> 解法：用年度收益数据跑 Bailey et al. (2014) DSR 和 **Cohen et al. (2020) CSCV**。

`[核对事实]` `stocks/pbo_dsr.py` 的 `pbo_cscv()`：

- 做法是 **5 折扩张窗口滚动**（`for i in range(n_folds)`，训练取 `returns_panel.iloc[:tr_end]`，测试取紧随其后的一折）；
- PBO 取 `pbo = max(0.0, min(1.0, gap / ios_mean))`，其中 `gap = IS 最优夏普 − 该策略 OOS 夏普`；
- 输入 T=11（完整年）、`n_folds=5` ⇒ 有效测试折仅 4 个。

`[推导]` 上述实现与 CSCV 的标准定义（组合 S 个子集、按 OOS 排名统计「IS 最优者落到 OOS 中位数以下」的比例）**不是同一方法**；且把结果 `clamp` 到 `[0,1]` 属实现自定。⇒ **当前输出的「PBO = 100%」不能直接作为标准 CSCV 定义下的 PBO 结果引用**，应标为「实现与方法定义不一致」的**待核实项**。

`[建议]`（未经授权）把该项单列为 §8 待裁决；**本轮不重算、不改代码、不据此宣布 PBO 机制整体无效**。

### 2.5 诊断结论（三条判定句）

1. `[推导]` **F1 的判别标准是「是否按检验次数校正」，不是阈值高低** —— 这决定了 §3 的三条路线中，只有涉及校正的路线才真正改变 F1 关系。
2. `[推导]` **1.10 的三个输入（N、α、T）是本项目的自定参数**，其出处留档不完整（§8）；诊断停在「输入依据待核实」，不裁决对错。
3. `[推导]` **DSR/PBO 一节的证据强度需要重新评估**：一个待核实的实现差异（§2.4）+ 一个未留推导的「等价 F1」判断（§2.3）都会影响 §9.4「5 候选全灭」这一结论的强度 —— **但本轮不重算，也不撤销该结论**。

## 3. 重建路线比较（三条，统一六维度）

**统一比较维度**：① 解决什么问题 ② 依赖什么假设 ③ 可能误杀什么 ④ 可能漏放什么 ⑤ 需要什么独立证据 ⑥ 所需人工/算力成本（分一次性改造 / 后续持续，未知标「未知」）。

### 路线 A · 修正多重检验口径

| 维度 | 内容 |
|---|---|
| ① 解决什么 | `[建议]` 把校正真正落到「判据」上：修正 PBO 实现（§2.4）、明确 N 的计数口径、把 A/B 线与校正挂上关系 |
| ② 依赖假设 | `[建议]` 假设「检验次数可被诚实、完整地计数」。若历史搜索次数无法复原（早期零散探索、未记录的动作），该假设置疑 |
| ③ 可能误杀 | `[推导]` N 越大阈值越高；若把「事实上没搜过的组合」也计入 N，会抬高门槛而过严。参考 `[原文]` §12.4-1：「弱但真实的因子会被主动放弃」 |
| ④ 可能漏放 | `[建议]` N 计数不足或校正过度保守时，真信号仍被拦；这与现状同向，不改善 |
| ⑤ 独立证据 | `[推导]` 需要**留档的搜索计数**（N 的可复现来源）；标准 CSCV 下的 PBO 复算（须在重启后、用冻结口径） |
| ⑥ 成本 | `[建议]` 一次性：中（改代码 + 复算，属重启后动作）；持续：低（口径固定后不再改）。**具体人天/算力未知** |

### 路线 B · 更换样本外判据

| 维度 | 内容 |
|---|---|
| ① 解决什么 | `[建议]` 用**干净窗口**（§9.1 冻结制度）替代「同段确认」的伪样本外，从结构上解决 F2，也间接缓解 F1 |
| ② 依赖假设 | `[原文]` 依赖冻结制度成立（§9.1：冻结点、数据快照哈希、机器闸）。假设「冻结后数据未被历史改写」—— 故需面板 sha256 闸 |
| ③ 可能误杀 | `[推导]` 干净窗口期短（§9.1：第一个能判决的时点 ≈ 冻结后 12 个月），1~2 期判不了年化 ⇒ 可能在证据不足时把候选停在「无法判定」，而非判活 |
| ④ 可能漏放 | `[推导]` 长冻结期意味着新信号长期无法被确认 ⇒ 漏放风险主要落在「时间」而非「统计」 |
| ⑤ 独立证据 | `[原文]` 干净窗口数据本身（观测日 > 冻结 timestamp）；`[建议]` 截至本文档，该窗口尚未产出可判决读数 |
| ⑥ 成本 | `[建议]` 一次性：低（制度已建成，§9.1）；持续：**时间成本 = 等待**（至 2027-10 第一个判点）。**人天未知** |

### 路线 C · 调整现有阈值

| 维度 | 内容 |
|---|---|
| ① 解决什么 | `[建议]` 调整 1.10 的输入（N / α / T）以匹配「5 个候选」这一实际搜索规模 |
| ② 依赖假设 | `[建议]` 假设「实际搜索规模 N 可以被一个小得多的值诚实刻画」 |
| ③ 可能误杀 | `[推导]` 降阈值 = 放宽门槛 ⇒ **误杀减少、漏放增加**，方向与 A 相反 |
| ④ 可能漏放 | `[推导]` **这是三条路线里漏放风险最高的一条**：若 N 的真实值就是 191，降阈值等于人为把已探明的过拟合放进来 |
| ⑤ 独立证据 | `[建议]` 需要 N 的独立核算 + 一份「为什么实际搜索规模小于 191」的可核验论证 |
| ⑥ 成本 | `[建议]` 一次性：低（只改参数）；持续：未知。**代价主要不在成本，而在证据** |

`[推导]` **三条路线不对称**：A 追求「校正到位」，B 追求「结构上真样本外」，C 追求「阈值与实际搜索匹配」。`[建议]` 不得预设任一条胜出；C 尤其**不得被包装成默认修复方案** —— 以「让候选通过」为动机的降阈值，与 §14.2 所禁的「事前判据的事后选择」同构。

## 4. 误杀与漏放分析（机制风险，不用候选结果裁定）

`[原文]` `研究方法与验证协议.md` §12.4 两条既有的「会误杀」提醒：

> 1. **弱但真实的因子会被主动放弃**：F5 + 量级线的组合意味着「不到线就停投」。这是设计取舍（宁可错杀，因为错杀成本是少一个因子、漏过成本是真金白银，§6），不是判错。
> 2. **执行 / 参数类的优势拿不到证据也拿不到否证**：这类策略在本流程里既过不了关、也证不了伪——因为没有测它的统计量。

| # | 机制风险 | 受影响的路线 | 是否可用现有材料判定 |
|---|---|---|---|
| 1 | 校正阈值抬高 → 弱真信号被放弃 | A、C(反向) | `[建议]` 否，须重启后实证 |
| 2 | 干净窗口期太短 → 长期停在「无法判定」 | B | `[推导]` 部分可判（§9.1 已给时间结构） |
| 3 | 搜索计数不可复原 → 校正无法落地 | A | `[建议]` 否，须先做 §8-1 |
| 4 | 降阈值 → 漏放已探明的过拟合 | C | `[建议]` 否，须先做 N 的独立核算 |
| 5 | 换交易类型时判据载体失效（非阈值问题） | 全部 | `[原文]` §12.5：F 码跨域成立，但载体（截面统计量）不成立 |

`[推导]` 本节的目的是**先把风险列全**，为 §5 的证据分级提供依据；**不以任何候选的实际读数判定风险大小**。
